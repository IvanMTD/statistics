# statistics

Статическое веб-приложение для проверки книги Excel по правилам из `ruleset.json`.

Пользователь загружает файл `.xlsx`, нажимает «Проверить», и приложение выдаёт список найденных ошибок. Вся логика работает в браузере: Excel разбирает SheetJS, формулы считает собственный движок (`js/formula-engine.js`), а сами правила лежат в `ruleset.json`.

## Структура проекта

- `index.html` — интерфейс (загрузка файла, кнопка проверки, вывод ошибок).
- `js/main.js` — чтение файла и отображение результатов.
- `js/parser.js` — загрузка правил, их разбор и формирование сообщений об ошибках.
- `js/formula-engine.js` — универсальный движок формул Excel.
- `ruleset.json` — правила проверки (JSON-массив).
- `tests/engine.test.js` — тесты движка и правил.
- `Dockerfile`, `nginx.conf`, `docker-compose.yml` — сборка и запуск в Docker.

## Как это работает

Каждое правило описывает условие ошибки формулой Excel. Если формула вернула **ИСТИНА**, правило считается сработавшим и в отчёт попадает ошибка. Если ЛОЖЬ — ошибки нет.

## ruleset.json

Файл — это JSON-массив. Каждый элемент массива — одно правило:

```json
{
  "id": 15,
  "formula": "=И(СУММ('Раздел 2'!$Q11:$R11)<'Раздел 2'!$L11)",
  "error": "${section}, строка ${row}: заполните графы 11 и 12 (сейчас ${value})",
  "rows": ["11-323"]
}
```

### Поля правила

| Поле | Обязательно | Описание |
| --- | --- | --- |
| `id` | нет | Число или строка. Нужно только для сообщения в консоли, если формулу не удалось разобрать. |
| `formula` | да | Формула Excel — условие ошибки. |
| `error` | нет | Текст ошибки с подстановками `${...}` (см. ниже). Без него сообщение будет пустым. |
| `rows` | нет | На какие строки распространяется правило. |
| `ranges` | нет | Список диапазонов ячеек, по которым правило обходит каждую ячейку (см. ниже). |
| `section` | нет | Переопределяет раздел в `${section}`. По умолчанию раздел — имя листа ячейки, на которой сработало правило. |

### formula

Пишется как в Excel:

- Ведущий знак `=` можно не писать.
- Разделитель аргументов — `;` или `,`.
- Имя листа — в одинарных кавычках: `'Раздел 2'!$Q11`.
- Формула может ссылаться на любые листы книги, не только на тот, к которому относится правило.

### rows

Массив строк, на которые распространяется правило:

- `"11-323"` — диапазон строк с 11 по 323;
- `"11"` — одна строка.

Для каждой строки диапазона формула считается отдельно, поэтому номера строк в формуле пишутся **относительными** (например `$Q11:$R11`).

- Номер строки со знаком `$` при подстановке `rows` **не сдвигается**.
- Без `$` — сдвигается на номер текущей строки.
- Колонки никогда не сдвигаются — сдвигаются только номера строк.
- Без поля `rows` формула считается один раз как есть.

### ranges

Список диапазонов ячеек. В формуле пишется плейсхолдер `@` — «текущая ячейка». Движок обходит **каждую ячейку** каждого диапазона, подставляет `@` и считает формулу; все сработавшие ячейки собираются в одну ошибку (их адреса попадают в `${cells}`).

- Диапазоны указываются с листом: `"Раздел 2!I11:J16"` или без листа: `"I11:J16"`.
- Допускаются `$`: `"Раздел 2!$I$11:$J$16"`.

Пример — найти все ячейки, в которых забиты формулы:

```json
{
  "id": 19,
  "formula": "=ЕФОРМУЛА(@)",
  "error": "В ячейках ${cells} забиты формулы",
  "ranges": ["Раздел 2!I11:J16", "Раздел 2!M11:AF16"]
}
```

`ranges` и `rows` — взаимоисключающие: если заданы `ranges`, поле `rows` игнорируется.

### Подстановки в error

В тексте `error` можно использовать переменные `${...}`:

| Переменная | Что подставляет |
| --- | --- |
| `${section}` | Раздел (имя листа) ячейки-свидетеля, например «Раздел 2», либо значение поля `section`. |
| `${row}` | Номера строк ячеек-свидетелей через запятую: «11» или «11, 12». |
| `${col}` | Буквы столбцов ячеек-свидетелей через запятую, например «Q, R». |
| `${value}` | Значения ячеек-свидетелей через запятую. Пустая ячейка — «(пусто)», ошибка — её код, например `#ССЫЛКА!`. |
| `${cells}` | Адреса ячеек-свидетелей через запятую. Имя листа добавляется только когда ячейки из разных листов: «Q11, R11» или «Раздел 3!M13, Раздел 2!N13». |

Неизвестный `${ключ}` остаётся в тексте как есть.

### Ячейки-свидетели

В `${cells}`, `${value}`, `${row}` и `${col}` попадают только те ячейки, которые реально прочитала формула:

- Если формула собрана через `И` / `ИЛИ`, движок оставляет аргументы, совпавшие с итогом: для `И` — ложные, для `ИЛИ` — истинные. Поэтому в сообщение попадают именно проблемные ячейки, и от них же берётся `${section}`.
- Числа и текстовые константы в формуле ячеек не добавляют.

### Операторы

- Сравнение: `= <> < > <= >=`
- Склейка текста: `&`
- Арифметика: `+ - * / ^` и унарные `+ -`
- Скобки: `( )`
- Текстовые константы в двойных кавычках
- Коды ошибок: `#ССЫЛКА!`, `#ЗНАЧ!`, `#Н/Д`, `#ДЕЛ/0!`, `#ИМЯ?`, `#ЧИСЛО!`, `#ПУСТО!`
- Логические константы: `ИСТИНА`, `ЛОЖЬ`, `TRUE`, `FALSE`

### Функции

- **Логические:** `И`, `ИЛИ`, `НЕ`, `ЕСЛИ`, `ЕСЛИОШИБКА`, `ИСТИНА`, `ЛОЖЬ`
- **Проверки:** `ЕЧИСЛО`, `ЕТЕКСТ`, `ЕПУСТО`, `ЕЛОГИЧ`, `ЕОШИБКА`, `ЕНД`, `ЕФОРМУЛА`
- **Текст:** `ДЛСТР`, `СЖПРОБЕЛЫ`, `ПРОПИСН`, `СТРОЧН`, `ЛЕВСИМВ`, `ПРАВСИМВ`, `ПСТР`, `СЦЕПИТЬ`, `ПОДСТАВИТЬ`, `ПОВТОР`, `НАЙТИ`, `ПОИСК`, `ЗНАЧЕН`
- **Математика:** `СУММ`, `ПРОИЗВЕД`, `МИН`, `МАКС`, `СРЗНАЧ`, `СЧЁТ`, `СЧЁТЗ`, `ОКРУГЛ`, `ОКРУГЛВВЕРХ`, `ОКРУГЛВНИЗ`, `ЦЕЛОЕ`, `ОСТАТ`, `ABS`, `КОРЕНЬ`, `СТЕПЕНЬ`, `ЗНАК`
- **Ссылки:** `ВПР`, `ГПР`, `ПОИСКПОЗ`, `ИНДЕКС`, `СТРОКА`, `СТОЛБЕЦ`, `ЧСТРОК`, `ЧИСЛСТОЛБ`
- **Английские синонимы** — те же функции: `SUM`, `IF`, `AND`, `OR`, `NOT`, `LEN`, `LEFT`, `RIGHT`, `MID`, `FIND`, `COUNT`, `COUNTA`, `ROUND`, `INT`, `MOD`, `SQRT`, `ABS`, `VLOOKUP`, `HLOOKUP`, `INDEX`, `MATCH`, `ROW`, `COLUMN`, `ISFORMULA` и другие.

### Отсутствующие данные

Если лист или ячейка не существует, формула возвращает `#ССЫЛКА!`, правило не срабатывает, и в отчёт ничего не попадает — на незаполненной книге нет лавины ложных ошибок.

### Пример

Правило:

```json
{
  "id": 15,
  "formula": "=И(СУММ('Раздел 2'!$Q11:$R11)<'Раздел 2'!$L11)",
  "error": "${section}, строка ${row}: проверьте ${cells} (значения: ${value})",
  "rows": ["11-323"]
}
```

Сообщение при срабатывании:

```
Раздел 2, строка 11: проверьте Q11, R11, L11 (значения: 3, 4, 10)
```

## Запуск

### Локально (браузер)

Правила загружаются из `ruleset.json` рядом с `index.html`, поэтому открывать страницу нужно через HTTP-сервер, а не как `file://`. Например:

```bash
python -m http.server 8000
# http://localhost:8000
```

### Docker

```bash
docker compose up -d --build
# http://localhost:8002
```

## Тесты

```bash
node tests/engine.test.js
```
